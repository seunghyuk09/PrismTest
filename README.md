# PrismTest

**스마트폰 카메라로 투명 프리즘의 표면 얼룩을 실시간 판정하는 검사 시스템**

폰을 지그에 고정하고 프리즘을 안착부에 올리면, 앱 화면에 즉시 PASS / FAIL이 뜬다.
판정은 사람 눈이 아니라 재현 가능한 **수치(결함 지수 + 임계값)** 로 낸다.

---

## 왜 표면 얼룩인가

2026-01-23 기준 n=15,120 불량 파레토:

| 항목 | 수량 | 비율 |
|---|---:|---:|
| 양품 | 8,328 | 55.08% |
| **표면 얼룩** | **5,843** | **38.64%** |
| 흰색 이물 | 512 | 3.39% |
| 스크래치 | 244 | 1.61% |
| 검정색 이물 | 118 | 0.78% |
| 페인트 얼룩 | 75 | 0.50% |
| Diffuser 얼룩 / Dig / 파손 / 내부 기포 / 내부 백태 | 0 | 0.00% |

**표면 얼룩 하나가 전체 불량의 87.9%.** 여기만 잡아도 효과의 대부분을 가져간다.

단, 이 비율이 비정상적으로 높다는 것 자체가 신호다. 실제로 공정에 원인이 있거나,
검사원이 애매한 것을 전부 "표면 얼룩"으로 몰아넣고 있거나 둘 중 하나다.
후자라면 그 라벨로 만든 알고리즘은 처음부터 틀린다.
→ **라벨 순도 검증(재세정 테스트)이 모든 작업의 1순위다.**

## 대상물

직각 삼각 프리즘. 검사 시점에는 **완전 투명**하다.
(참고 사진은 흑색 페인트가 도포된 상태이며, 검사 조건과 다르다.)

실제 치수·재질·유효 검사면·페인트 유무 조건은 아직 미확정 —
`docs/open-questions.md` 참조.

## 접근 방법

### 1. 광학이 8할
알고리즘으로 억지로 짜내기 전에, 조명으로 결함을 **눈에 보이게** 만든다.
투명체 표면 얼룩의 기본안은 **암시야(dark-field)** — 흑색 배경에 저각도 측면광을 주면
얼룩이 산란시킨 빛만 카메라로 들어와 검은 배경 위에 밝게 뜬다.

합격 기준: 원본 프레임에서 얼룩의 국부 대비 **ΔI/I ≥ 5% (목표 15%)**.
이 수치가 안 나오면 알고리즘 단계로 넘어가지 않는다.

### 2. 모든 촬영 조건 고정
ISO·셔터·초점·화이트밸런스·줌을 전부 수동 고정한다.
HDR, 씬 최적화, 나이트 모드는 전부 OFF.
제조사 후처리(샤프닝·노이즈 리덕션)는 미세 얼룩을 왜곡한다.

### 3. 판정의 수치화
```
A_ratio = 결함면적합 / 유효검사면적          # 면적 비율
C_max   = max(ΔI/I)                          # 최대 국부 대비
C_int   = Σ(ΔI/I × 화소수) / 유효화소수      # 적분 대비 (전체 흐림도)

SI(얼룩 지수) = 100 × clip(w1·A_ratio/A_ref + w2·C_max/C_ref + w3·C_int/Ci_ref, 0, 1)

SI < T_pass  → PASS
SI ≥ T_fail  → FAIL
그 사이       → 재검 (사람 확인)
```
초기 운영은 재검 구간을 넓게 잡고, 데이터가 쌓이면 좁힌다.
**미검(escape)을 과검(overkill)보다 훨씬 무겁게 다룬다.**

### 4. 판정 불가는 정직하게 판정 불가로
초점 불량·노출 이상·미안착·글레어 프레임은 억지로 판정하지 않고
"재촬영 / 재안착"을 띄운다.

## 지원 기기 정책

1차 검증 기기는 갤럭시 Z 폴드 7. 이후 iPhone 포함 타 기종으로 확대한다.
다만 **"아무 폰이나 설치하면 검사됨"은 성립하지 않는다** —
기기마다 센서·렌즈·ISP가 달라 같은 프리즘도 다른 지수가 나온다.

- 알고리즘은 **C++ 공용 코어 하나**로 짜고 iOS·Android가 동일하게 호출한다
  (Kotlin과 Swift로 각각 구현하면 반드시 값이 갈라진다)
- 기기마다 **캘리브레이션 프로파일**(노출·초점·px/mm·플랫필드·σ0·임계값)을 만든다
- 프로파일이 없는 기기는 앱이 **판정 불가로 잠근다**
- 신규 기기는 등가성 검증(**Kappa ≥ 0.80, R² ≥ 0.90**, 한도견본 전건 일치)을 통과해야 등록

자세한 내용과 iOS 제약(ISP 후처리 비활성화 불가, 사이드로드 불가)은
[`docs/platform-strategy.md`](docs/platform-strategy.md) 참조.

## 서브에이전트

| 에이전트 | 역할 |
|---|---|
| `prism-optics-jig` | 조명·광학 배치, 기기 교체식 지그 설계, 촬영 조건 고정 |
| `prism-defect-taxonomy` | 결함 정의·광학적 시그니처·데이터셋/라벨링 프로토콜 |
| `prism-vision-algo` | 영상처리 파이프라인, 결함 지수 산출 |
| `prism-mobile-app` | iOS·Android 실시간 검사 앱 (공용 C++ 코어 + 네이티브 셸) |
| `prism-calibration` | 임계값 결정, 과검/미검, Gauge R&R, 기기 간 등가성 검증 |

## 진행 순서

1. `prism-defect-taxonomy` — 얼룩 라벨 순도 확인 + 한도견본 정의 ← **여기가 먼저**
2. `prism-optics-jig` — 조명 후보 3안 비교 촬영, ΔI/I 실측으로 1안 선정
3. `prism-vision-algo` — Python 프로토타입, ROC로 검증
4. `prism-calibration` — 임계값 확정, Gauge R&R
5. `prism-mobile-app` — C++ 코어 + Android 셸, 수치 일치 검증, 파일럿
6. iOS 셸 추가 → 기기 등가성 검증 → 기종 확대

**1~5는 폴드 7 한 대로 끝낸다.** 알고리즘이 확정되기 전에 기기를 늘리면
문제가 알고리즘 탓인지 기기 탓인지 구분할 수 없다.
단, 코드 구조는 처음부터 공용 C++ 코어로 간다.

## 현재 상태

설계 단계. 실물 샘플 촬영 전이다.
시작 전에 확정해야 할 항목은 [`docs/open-questions.md`](docs/open-questions.md)에 있으며,
특히 **프리즘 실치수 / 검출 최소 얼룩 크기(mm) / 한도견본 현물 유무**가 없으면 설계가 헛돈다.
