# 자동 업데이트

## 원칙 — 앱은 네트워크를 갖지 않는다

이 앱은 제품을 촬영하므로 **INTERNET 권한을 갖지 않는 것**이 핵심 안전 속성이다
(`docs/app-security.md`). 자동 업데이트를 위해 앱에 네트워크 권한을 주면
"촬영물이 밖으로 나갈 경로가 없다"는 보장이 깨진다.

**해법은 앱이 아니라 다른 쪽이 업데이트를 맡는 것이다.**
스토어나 전용 업데이터가 새 버전을 받아오고, 앱 자신은 계속 오프라인으로 남는다.

| 방식 | 앱 네트워크 권한 | 준비 | 편의성 |
|---|---|---|---|
| **Obtainium** | 불필요 ✓ | 즉시 | 알림 → 한 번 눌러 설치 |
| **Play 내부 테스트** | 불필요 ✓ | 계정 등록 며칠 | 완전 자동 |
| 앱 내 업데이터 | **필요 ✗** | 즉시 | 완전 자동 |

권장: **지금은 Obtainium, 최종적으로는 Play 내부 테스트.**

---

## 방법 1 — Obtainium (오늘 바로)

Obtainium 은 GitHub 릴리스를 감시해 새 버전이 올라오면 알려주는 오픈소스 앱이다.
네트워크 권한은 Obtainium 이 갖고, PrismScope 는 계속 오프라인으로 남는다.

### 설치
1. https://github.com/ImranR98/Obtainium/releases/latest 에서 APK 다운로드
   (`app-release.apk` 계열 파일)
2. 설치 — 처음 한 번은 삼성 자동 차단을 꺼야 한다

### 등록
1. Obtainium 실행 → 하단 **Add App**
2. **App Source URL** 에 입력
   ```
   https://github.com/seunghyuk09/PrismTest
   ```
3. **Add** — PrismScope 가 목록에 잡힌다
4. 설정에서 백그라운드 확인 주기를 정한다 (기본 3시간이면 충분)

### 이후
새 빌드가 올라오면 알림이 뜨고, 눌러서 설치하면 끝이다.
같은 서명 키를 쓰므로 덮어쓰기 설치되고 기존 측정 데이터는 유지된다.

> **주의**: Obtainium 도 설치할 때마다 삼성 자동 차단이 켜져 있으면 막힌다.
> 자동 차단을 끈 상태로 두거나, 업데이트할 때만 잠시 끈다.
> 이 마찰까지 없애려면 Play 내부 테스트로 가야 한다.

## 방법 2 — Play 내부 테스트 (최종형)

Play 를 통해 배포하면 **자동 차단도, Play Protect 경고도, 수동 설치도 없다.**
업데이트는 Play 가 백그라운드에서 알아서 내려준다. 앱은 여전히 네트워크 권한이 없다.

절차는 `docs/play-release.md` 참조. 계정 등록에 며칠 걸리므로 미리 시작해 둔다.

### CI 자동 업로드 붙이기 (계정 준비 후)
Play Console → 설정 → API 액세스 → 서비스 계정 생성 → JSON 키 발급 →
저장소 시크릿 `PLAY_SERVICE_ACCOUNT_JSON` 에 등록.

그다음 워크플로에 업로드 단계를 붙이면 **푸시 → 빌드 → Play 내부 테스트 자동 배포 →
폰에서 자동 업데이트**까지 사람 손이 닿지 않는다.

지금은 붙이지 않았다. 계정이 없는 상태에서 넣으면 매 빌드가 실패한다.

## 방법 3 — 앱 내 업데이터 (권장하지 않음)

앱이 직접 GitHub 를 확인하고 새 APK 를 받아 설치하는 방식이다.
가장 매끄럽지만 **앱에 INTERNET 권한과 REQUEST_INSTALL_PACKAGES 권한을 줘야 한다.**

그 순간 아래가 무너진다.
- "촬영물이 밖으로 나갈 경로가 없다"는 구조적 보장
- CI 의 금지 권한 검사 (통과시키려면 검사 자체를 완화해야 한다)
- 사내에 "이 앱은 통신하지 않는다"고 설명할 근거

안드로이드에는 "특정 도메인만 접속 허용" 같은 매니페스트 수준 장치가 없다.
INTERNET 권한을 주면 앱은 **어디로든** 접속할 수 있고, 남는 것은
"코드를 믿어달라"뿐이다. 구조적 불가능이 코드 신뢰보다 강하다.

필요하다고 판단되면 넣을 수 있다. 다만 **무엇을 내주는지 알고 결정해야 한다.**

## 릴리스 방식

업데이터가 새 버전을 인식하려면 **태그가 매번 달라야 한다.**
고정 태그(`apk-latest`)를 덮어쓰면 버전이 올라간 것을 인식하지 못한다.

그래서 빌드마다 버전 태그로 릴리스한다.

```
v5  → PrismScope v0.1.5  → PrismScope-b5.apk / .aab
v6  → PrismScope v0.1.6  → PrismScope-b6.apk / .aab
```

- 항상 최신을 가리키는 주소: https://github.com/seunghyuk09/PrismTest/releases/latest
- `versionCode` 와 `versionName` 은 CI 빌드 번호에서 자동으로 올라간다
- 앱 화면 **설정** 안에 현재 버전이 표시되고, 측정 CSV 의 `appVersion` 열에도 기록된다
  → 어느 빌드로 잰 측정인지 나중에 추적할 수 있다
