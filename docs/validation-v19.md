# v19 폰 안의 디그 검증기

검사 화면의 **검증기**를 누른다. 카메라 권한이 없는 화면에서도 **사진·영상 검증기 열기**로 들어갈 수 있다. 별도 화면으로 열려 실시간 CameraX 분석이 멈추며, 검증을 닫으면 실시간 검사로 돌아간다.

## 먼저 해볼 테스트

1. **내장 디그 예시 → 이 장면 비교하기**: 사용자가 `Video Project 2`의 약 2초 장면에서 디그라고 확인한 두 위치가 미리 표시되어 있다. 기본 허용 오차는 분석 이미지의 5px이다. 두 점을 찾았는지와 추가 후보를 확인한다.
2. **코어 자체 검증 실행**: 균일 배경, 핫픽셀, 두 점, 긴 반사선, 밝은 띠, 밝기 기울기, 작은 잡음, 90도 회전, Y 평면의 패딩·픽셀 간격, 잘못된 버퍼의 열 가지 입력을 앱의 실제 Kotlin → JNI → C++ 경로로 검사한다.
3. **사진·영상 열기**: 폰에 있는 검사 영상을 선택한다. 영상은 시각을 맞춘 뒤 **프레임 열기**를 누른다. 검사면의 어두운 영역을 드래그하면 확대되어 실제 디그 중심을 눌러 정답을 표시할 수 있다.
4. **이 장면 비교하기** 후 찾은 정답·놓친 정답·추가 후보를 확인한다. 초록은 정답, 빨강은 놓친 정답, 노랑은 검출 후보다. 정답 원과 후보 원은 실제 디그 크기가 아니다.
5. **HTML 저장**은 검사 영역의 원본 PNG와 위치 표시를 포함한다. **JSON 저장**은 정답·모든 출력 후보·설정·시각·기기·시간 측정을 기록한다. 두 파일 모두 Android 파일 선택기로 저장 위치를 정한다.

처음부터 불량 사진을 많이 모을 필요는 없다. 내장 예시와 자체 검증으로 앱 연결과 좌표를 점검한 뒤, 사용자가 확인할 수 있는 샘플부터 추가한다.

## 정답 표시와 결과 해석

- 한 후보는 정답 하나에만 연결한다. 허용 오차 안에서 일대일 연결 수가 최대가 되도록 비교한다.
- 일부 점만 표시했다면 표시한 점에 대한 일치율만 계산한다. 추가 후보는 **미분류**다. 정밀도·재현율이나 오검출률을 만들지 않는다.
- **이 영역의 모든 디그를 표시했습니다**를 직접 체크한 경우에만 해당 장면의 정밀도와 재현율을 계산한다. 추가 후보는 오검출 후보로 기록한다. 양품 영역은 정답 0개로 체크할 수 있다. 분모가 0인 지표는 `—`/JSON `null`로 남긴다.
- 비교에는 출력된 모든 후보를 사용한다. 화면의 기본 표시만 상위 8개로 제한하며, 모두 표시할 수도 있다. 코어의 출력 상한은 32개다. 32개가 나왔을 때는 일부 후보가 생략될 수 있음을 표시한다.
- 내장 예시는 양품이 아니다. 사용자가 확인한 두 디그가 있는 **한 개의 불량 실물**이다. 나머지 점들은 정답이 미확인이다. 이전의 양품 사진에 보이던 가운데 반사선은 디그 정답으로 사용하지 않는다. 첫 번째 영상도 양품으로 가정하지 않는다.

## 영상에서 지켜야 할 조건

사진은 긴 변 최대 2048px, 영상은 최대 1920×1920 범위로 해독한다. 표시되는 이미지 크기를 기준으로 좌표·ROI·허용 오차를 계산한다. 축소와 영상 압축 때문에 작은 결함이 사라질 수 있다. 영상 해독 결과의 RGB를 회색으로 바꾸므로 실시간 카메라의 Y 버퍼와 밝기 값이 완전히 같지는 않다.

영상은 요청 시각에 가장 가까운 프레임을 연다. 프레임의 정확한 PTS를 측정했다고 주장하지 않는다. 시각이나 검사 영역을 바꾸면 정답 표시를 초기화한다. 움직인 프리즘에 이전 좌표를 복사하지 않기 위해서다.

**영상 반복 분석 실행**은 고정된 ROI로 최대 30장면을 샘플링해 후보 개수·마스킹 비율·코어 시간을 기록한다. 단일 프레임의 정답 좌표는 이 분석에 적용하지 않는다. 제품이 ROI 밖으로 움직이면 영역을 다시 잡거나 별도로 프레임을 열어 비교해야 한다. 샘플링은 전체 프레임 추적·실시간 FPS·시간에 걸친 디그 재식별 검증이 아니다.

## 실제 검사 성능을 확인하는 순서

같은 제품은 여러 각도로 찍어도 같은 **실물 샘플 ID**를 쓴다. 같은 제품의 여러 프레임을 독립적인 불량 개수로 세지 않는다. 검사 조건을 정하는 데 사용한 제품과 마지막 확인에 사용할 제품도 분리한다.

먼저 폰·거리·조명·노출·초점을 고정하고, 작은 검은 차광판이나 후드로 주변 반사를 줄인다. 양품과 디그 불량 각각을 다시 놓고 돌려가며 촬영해, 각도에 따라 보였다 사라지는 점이 실제로 검출되는지 확인한다. 양품의 반사선·먼지·글자·모서리를 디그로 잡는지도 확인한다. 닦으면 스크래치가 생길 수 있다는 사용자 조건에 따라, 무리한 닦기를 전제로 삼지 않는다.

검증기는 디그 **후보 위치**의 평가 도구다. 이물·스크래치·뿌연 불량·기포 구분, 세 면 전체의 검사 커버리지, 제품 단위 미검·과검, 60/40 규격과 mm 크기 판정은 별도 정답과 실측 검증이 필요하다. 앱의 5개 양품·3개 불량 등록 조건은 운영 기준을 만드는 최소 조건이며 통계적 성능 검증 표본 수가 아니다.

자체 검증의 P50/P95는 160×140 합성 입력으로 준비 5회 후 측정 40회의 **검출 코어** 실행 시간이다. 촬영·해독·RGB 변환·화면 표시를 제외한다. 실제 폰에서 실행해 얻은 값을 그 폰의 참고값으로 사용한다. 에뮬레이터나 개발 컴퓨터의 값은 실물 폰 성능을 나타내지 않는다.

## 개발자 회귀 검증

```sh
python3 analysis/validate_dig.py --sanitize --report out/native-validation.json
cd android
BUILD_NUMBER=19 ./gradlew testReleaseUnitTest assembleRelease
```

단위 검증은 일대일 연결, 정답 없음, 부분 정답의 지표 처리, 영역 경계, 영상 샘플링 상한, 보고서의 미분류 처리와 JSON 필드를 포함한다. 네이티브 검증은 합성 입력과 사용자 제공 장면의 두 정답 위치를 검사한다. 실물 폰의 카메라·조명·각도에 대한 검증은 폰에서 별도로 수행한다.
