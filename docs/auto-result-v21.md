# v21 검사 결과 사진 자동 저장

검사 모드에서 검사를 끝내면, 선택한 유형마다 **최고 점수가 나온 실제 장면**을 저장하고 결과 화면을 연다. 검사 종료 후 움직인 프리즘에 이전 좌표를 덧그리지 않는다. 샘플 등록 모드의 동작은 그대로다.

## 폰에서 사용

1. 조명·검사 영역·촬영 조건을 맞추고 고정한다.
2. 필요한 검사 유형을 선택하고 **검사 시작**을 누른다.
3. 여러 각도로 돌려 관찰한다. 종료 후 사진·기록이 자동 저장되고 결과 사진이 열린다.
4. 유형별 탭에서 해당 유형의 최고 점수 장면을 확인한다. **의심 위치 표시 / 원본 휘도 사진**을 바꿔 비교할 수 있다.
5. **검사 화면으로** 돌아가면 다음 검사를 할 수 있다. **직전 결과**는 앱을 다시 열어도 사용할 수 있다.

사진은 `Pictures/PrismScope/Results`, 기록 JSON은 `Documents/PrismScope/Results`에 저장한다. 저장소 권한을 추가하지 않고 MediaStore를 사용한다. 갤러리·파일 앱에서도 확인할 수 있다. 저장 중에는 새 검사 시작을 막고, 실패 시 **직전 결과 자동 저장 다시 시도** 버튼을 제공한다. 재시도 전에 새 검사를 시작하면 메모리에 남은 이전 결과는 교체된다.

## 표시의 의미

- **디그:** v26부터 해당 장면의 후보를 점수순으로 최대 10곳 표시한다. **1–3번은 빨강, 4–6번은 주황, 7–10번은 노랑**이며 이후 번호는 그리지 않는다. 원과 번호를 같은 색으로 표시한다. 원은 의심 위치 표시이며, 실제 디그 크기나 모든 후보의 불량 확정을 뜻하지 않는다. [v26 표시 규칙](ranked-markers-v26.md)을 참고한다. 이전에 저장한 사진에는 당시 표시를 유지한다.
- **얼룩·흰색 이물·스크래치·검정 이물:** 현재는 영역 전체의 특징으로 점수를 계산하므로 분석 사각형과 최고 점수 장면을 저장한다. 개별 결함 위치를 산출했다고 표시하지 않는다.
- 유형별 최고 점수 시점이 다르면 사진도 다르다. 회전한 물체의 여러 장면을 한 사진의 좌표로 합치지 않는다.
- 반사광·관찰 변화 부족 등 검사 조건 문제가 있으면 재검으로 남기고 이유를 사진·기록에 표시한다. 유효 영상이 하나도 없으면 확보된 첫 진단 장면을 따로 표시한다. 카메라 프레임 자체가 없으면 기록만 저장하고 사진이 없음을 알린다.
- 기준 샘플이 부족하면 **기준 없음**을 유지한다. 위치 표시가 생겼다는 이유로 판정을 불량·양품으로 바꾸지 않는다.

원본은 CameraX의 분석에 사용한 크롭된 **8비트 휘도(Y) 영상**을 표시 방향으로 돌린 무손실 PNG다. 센서 RAW나 기본 카메라의 컬러 사진은 아니다. 표시 사진은 원본 위에 사각형·후보 원을 그리고 설명을 영상 아래에 붙인다. 원본 사진에는 설명과 원을 그리지 않는다.

한 검사에서 선택한 유형 하나당 원본·표시 사진 2장과 검사당 JSON 1개를 저장한다. JSON에는 검사 ID·면·메모·최종 판정·재검 사유·유형별 점수와 기준·각 장면의 타임스탬프·촬영 조건·후보 좌표·사진 URI를 남긴다. 기록 형식은 `prism-inspection-v1`이다. 기존 수동 사진·CSV 파일은 보존한다.

## 검증

v21에서 JVM 단위 테스트 44개가 통과했다. 유형별 최고 장면 유지, 동일 장면 공유, 종료 후 늦은 프레임 거부, 0점 사진 유지, 잘못된 버퍼, 크롭·stride·회전 좌표, 기록의 장면별 좌표·URI 처리를 포함한다.

Android 11 x86_64 소프트웨어 에뮬레이터에서 **릴리스 APK**를 대상으로 다음 3개 계측 테스트가 통과했다.

1. 제공된 디그 예시를 실제 분석 경로로 읽고 두 정답 위치가 검출되는지 확인한 뒤, 원본·표시 PNG와 JSON을 MediaStore에 저장·다시 읽고 결과 화면에서 사진을 확인했다. 원본의 화소 값도 비교했다.
2. 카메라 프레임이 없을 때 사진을 만들어내지 않고 재검 기록만 저장했다.
3. 기록 생성 실패를 유도해 부분 생성된 사진·기록이 정리되는지 확인했다.

실제 폰의 카메라·조명·바람·각도와 검사 종료 타이밍을 포함한 현장 검사는 별도로 필요하다. 테스트의 프레임 여러 장을 독립적인 제품으로 세지 않는다.

```sh
cd android
BUILD_NUMBER=21 ./gradlew testReleaseUnitTest assembleRelease assembleReleaseAndroidTest
# Android 기기/에뮬레이터를 연결한 경우
BUILD_NUMBER=21 ./gradlew connectedReleaseAndroidTest
```
