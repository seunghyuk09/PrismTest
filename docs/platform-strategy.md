# 크로스플랫폼 전략 (iOS + Android)

## 요구
"Z 폴드 7은 내 폰이라 예시로 든 것이고, 가능하면 모든 모바일 환경에서 되면 좋겠다."

## 결론 요약
| 질문 | 답 |
|---|---|
| iOS 지원 가능한가 | 가능. 카메라 수동 제어는 오히려 iOS가 더 일관적 |
| 어떻게 만드나 | **C++/OpenCV 공용 코어 1개 + 네이티브 셸 2개** |
| 아무 폰이나 되나 | **아니오.** 기기별 캘리브레이션 프로파일 + 인증 절차 필요 |
| 가장 큰 걸림돌 | iOS 배포(사이드로드 불가, 유료 계정·맥 필요) |

---

## 1. 왜 공용 C++ 코어인가

파이프라인을 Kotlin과 Swift로 각각 구현하면 **반드시 값이 갈라진다.**
리사이즈 보간, 가우시안 커널 구현, 경계 처리, 부동소수 누산 순서 차이만으로
SI가 수 % 어긋나고, 그 순간부터 "어느 폰으로 재도 같은 판정"이 깨진다.

```
core/          C++17 + OpenCV        ← 알고리즘은 여기 한 곳에만 존재
  prism_core.h   extern "C" ABI
android/       Kotlin + Compose, JNI, CameraX + Camera2Interop
ios/           Swift + SwiftUI, ObjC++ 브리지, AVFoundation
shared-tests/  golden.json — 세 환경에서 SI 일치(±1%) CI 검증
```

UI는 화면 4개뿐이라 Flutter/RN으로 얻는 이득이 작고, 카메라 제어와 프레임 경로는
어느 프레임워크를 써도 결국 네이티브로 직접 짜야 한다. → 네이티브 셸이 단순하다.

**웹앱(PWA)은 기본안에서 제외.** iOS Safari가 노출·ISO·초점 수동 고정을 사실상
지원하지 않아 "촬영 조건 고정"이라는 이 프로젝트의 대전제가 무너진다.
(배포가 압도적으로 쉽다는 장점이 있어, 요구가 강하면 실기 검증 후 재검토)

## 2. 플랫폼 비대칭 — 알고 시작해야 할 것

| 항목 | Android | iOS |
|---|---|---|
| 노출/ISO/초점/WB 수동 고정 | ✅ (Camera2 FULL 레벨 필요) | ✅ 전 기종, 더 일관적 |
| 노이즈 리덕션 OFF | ✅ | ❌ **불가** |
| 샤프닝(EDGE) OFF | ✅ | ❌ **불가** |
| RAW 접근 | ✅ | ✅ |
| 기기 파편화 | 큼 (제조사별 상이) | 작음 |
| 앱 배포 | APK 사이드로드 | **불가** — 아래 참조 |

→ iOS의 ISP 후처리는 끌 수 없다. **회피 대상이 아니라 관리 대상**이다.
   대응: (a) 기기별 프로파일로 흡수, (b) 판정용 확정 촬영은 RAW 경로 사용.

## 3. 2단 촬영 패턴
1. **실시간 프리뷰** — 안착·초점·글레어 가이드용. 예비 지수 표시. 15 fps+
2. **확정 촬영** — 게이트 통과 후 고해상도(가능하면 RAW) 캡처.
   **이 값이 기록되는 공식 판정값.** 프리뷰 값은 참고용임을 UI에 명시.

실시간성과 화질을 모두 얻고, iOS의 ISP 제약도 완화된다.

## 4. 기기 확대 절차 (기종당 반복)
1. 최소 요건 확인 — 수동 제어 API, MFD, px/mm, 줌 없이 FOV 확보, 플리커
2. 어댑터 플레이트 제작 (지그 베이스는 공용, 플레이트만 기종별로 교체)
3. 작업거리 확정 → 플랫필드·화이트 레퍼런스 촬영
4. 양품 30개 × 3회 → σ0 산출 → **기기 전용 임계값**
5. 기준기와 등가성 검증: **Kappa ≥ 0.80, R² ≥ 0.90, 한도견본 전건 일치**
6. 통과 시 화이트리스트 등록. 실패 시 미지원 기기로 확정

**기기 하나 늘리는 데 실측 + 캘리브레이션 + 검증 공수가 든다.**
초기에는 우선 지원 2~3기종만 정하고 시작하는 것을 권한다.

## 5. iOS 배포 — 가장 현실적인 걸림돌
안드로이드는 APK 던져주면 끝이지만 iOS는 아니다. **전부 유료 계정이 필요하다.**

| 방식 | 비용/조건 | 적합성 |
|---|---|---|
| **TestFlight** | $99/년, 최대 10,000명, 빌드 90일 만료 → 주기 재배포 | 파일럿에 가장 무난 |
| **Ad Hoc** | $99/년, UDID 등록 연 100대, 프로파일 1년 | 검사 폰이 소수면 적합 |
| Apple Business Manager 커스텀 앱 | 조직 계정 필요 | 사내 정식 배포 |
| Enterprise Program | $299/년, 심사 엄격 | 대규모 사내 전용 |

추가로 **iOS 빌드에는 macOS + Xcode가 필수**다. 맥이 없으면 여기서 막힌다
(대안: Xcode Cloud, Codemagic 등 클라우드 CI — 비용·설정 사전 확인 필요).

## 6. 권장 진행
1차는 **Z 폴드 7 단일 기기로 알고리즘·임계값을 확정**한다.
기기를 늘리는 것은 그 다음이다. 검증되지 않은 알고리즘을 여러 기기에 퍼뜨리면
문제가 알고리즘 탓인지 기기 탓인지 구분할 수 없게 된다.

단, **코드 구조는 처음부터 공용 C++ 코어로** 짠다. 나중에 분리하는 비용이 훨씬 크다.
