# v24 컬러 저장과 HD~4K 화질 선택

새로 검사하거나 수동 촬영하는 사진을 **컬러 PNG**로 저장한다. 이전에 저장된 흑백 사진은 그대로 열 수 있다.

## 폰에서 사용

1. 검사 화면의 **화질**에서 HD·FHD·QHD·4K를 선택한다.
2. **수신 / 저장**에 표시되는 실제 크기를 확인한다. 세로 촬영에서는 3840×2160 영상이 회전 후 **2160×3840** 사진으로 저장된다.
3. **프리뷰** 해상도와 **분석 FPS**로 해당 폰의 화면·처리 상태를 비교한다. 속도가 아쉬우면 FHD 또는 HD로 바꿔 비교한다.
4. 조명·초점·노출을 맞추고 고정한 뒤 검사한다. 실제 분석 해상도가 달라졌으면 해당 조건의 양품·불량 기준을 등록한다.
5. 검사 종료 후 **원본 컬러 사진 / 의심 위치 표시**를 바꿔 보고, 두 손가락으로 확대한다.

| 선택 | 카메라에 요청하는 크기 |
|---|---|
| HD | 1280×720 |
| FHD | 1920×1080 |
| QHD | 2560×1440 |
| 4K | 3840×2160 |

크기는 요청값이다. 카메라의 지원 목록과 프리뷰·분석 스트림 조합에 따라 실제 크기를 선택한다. 높은 해상도 두 스트림을 동시에 연결하지 못하면 프리뷰를 먼저 낮춰 저장 원본 해상도를 유지하도록 시도한다. 그래도 연결되지 않으면 분석 해상도를 단계적으로 낮춘다. **4K를 선택했어도 실제 수신 크기가 더 낮으면 현재 조합에서 그 크기로 연결된 것이다.**

새 기본값은 FHD다. 이전 앱의 ‘표준’ 설정은 HD, ‘정밀’ 설정은 4K 선택으로 이어진다. 검사 영역 65%와 사용자가 조절해 저장한 크기는 유지한다.

## 저장 사진과 위치 표시

결함 점수는 카메라 영상의 휘도에서 계산하고, 사진은 **같은 프레임의 색상 정보까지 보존**해 저장한다. 원본은 카메라가 전달한 전체 프레임을 회전한 컬러 PNG다. JPEG 중간 압축이나 앱에서 화소 수를 늘리는 처리를 거치지 않는다. 센서 RAW 파일은 아니다.

실시간 화면은 화면비에 맞게 잘라 보여 줄 수 있다. 저장 사진에는 그 바깥의 실제 촬영 영역도 포함된다. 분석 사각형과 디그 후보 위치를 전체 사진 좌표로 옮겨 표시하며, 검사 종료 후 다른 각도에서 찍은 사진에 이전 위치를 덧그리지 않는다.

사진은 `Pictures/PrismScope/Results`, 검사 기록은 `Documents/PrismScope/Results`에 저장한다. 수동 사진도 전체 프레임 컬러 PNG이며, 수동 CSV는 `prismscope_log_v3.csv`에 남긴다. v3의 좌표는 저장 사진을 기준으로 하고, 분석 크롭·실제 분석 사각형을 추가로 기록한다. 이전 CSV·사진·검사 기록은 보존한다.

## 검증

단위 테스트 **57개**, Android 실행 테스트 **8개**가 통과했다. [실행 기록](https://github.com/seunghyuk09/PrismTest/actions/runs/45724666427)에 검증한 APK의 SHA-256과 통과 개수가 남아 있다. 검증한 파일을 재빌드하지 않고 다운로드 파일로 사용한다.

- 실제 3840×2160 YUV 테스트 데이터를 컬러 PNG로 저장하고, 회전 후 2160×3840 크기·색상·지정 화소 값을 확인했다.
- 패딩·픽셀 간격이 있는 Y/U/V 데이터를 복사한 후 원래 버퍼를 바꿔도 저장 사진이 보존되는지 확인했다.
- 전체 프레임으로 옮긴 후보 좌표와 분석 영역, 네 방향 회전, 색공간·신호 범위 변환을 확인했다.
- 수동 컬러 저장, 기존 휘도 기록 저장·열기, 프레임 없음·저장 실패 처리도 확인했다.
- HD/FHD/QHD/4K 선택, 검사 영역 조절, 화면 확대에 따른 공통 크롭 재연결을 확인했다.

실행 환경은 KVM을 사용한 Android 11 x86_64 가상기기다. 4K 데이터 저장 검증은 실제 폰의 4K 카메라 지원·렌즈 선명도·프레임률·결함 검출 정확도를 측정한 결과가 아니다. 폰에서는 실제 수신·저장 크기와 분석 FPS를 확인한다.
