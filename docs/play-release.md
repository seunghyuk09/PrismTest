# Google Play 내부 테스트 배포 절차

Play 내부 테스트로 배포하면 **삼성 자동 차단도, Play Protect 경고도 겪지 않고**
스토어를 통해 설치되며 업데이트도 자동으로 내려간다. 검사 폰이 여러 대면 이쪽이 정답이다.

## 먼저 — 이 작업은 계정 주인만 할 수 있다

아래는 대행이 불가능하다. 본인 확인, 결제 수단, 법적 계약 동의가 걸려 있기 때문이다.

- Google Play Console 개발자 계정 생성 (**최초 1회 $25**)
- 신원 확인 (개인: 신분증 / 법인: D-U-N-S 번호 — **법인은 발급에 며칠~수 주 걸릴 수 있다**)
- 개발자 배포 계약(DDA) 동의

**신원 확인에 시간이 걸리므로 오늘 바로 시작해두고, 그동안은 APK 사이드로드로 진행한다.**

### 개인 계정 vs 법인 계정
| | 개인 | 법인 |
|---|---|---|
| 확인 절차 | 신분증, 보통 1~2일 | D-U-N-S 번호 필요, 수 주 걸릴 수 있음 |
| 내부 테스트 | 가능 | 가능 |
| 프로덕션 출시 | 테스터 12명 × 14일 요건 있음 | 요건 없음 |

**내부 테스트(Internal testing)는 두 경우 모두 12명/14일 요건이 적용되지 않는다.**
사내 검사 도구는 프로덕션에 올릴 이유가 없으므로 내부 테스트만 쓰면 된다.
빠르게 시작하려면 개인 계정이 낫다.

## 1. 업로드할 파일

CI 가 매 빌드마다 `.aab` 를 만들어 릴리스에 첨부한다.

```
https://github.com/seunghyuk09/PrismTest/releases/tag/apk-latest
  └─ PrismScope-bN.aab   ← Play Console 에 올리는 파일
  └─ PrismScope-bN.apk   ← 사이드로드용 (Play 에는 올리지 않는다)
```

`.aab` 는 폰에 직접 설치할 수 없다. Play Console 전용이다.

## 2. 앱 만들기

Play Console → **앱 만들기**

| 항목 | 값 |
|---|---|
| 앱 이름 | PrismScope |
| 기본 언어 | 한국어 |
| 앱 또는 게임 | 앱 |
| 무료 또는 유료 | 무료 |

## 3. 내부 테스트 트랙에 업로드

**테스트 → 내부 테스트 → 새 버전 만들기**

- `.aab` 파일 업로드
- **Play 앱 서명**: 사용 설정(권장). 우리가 만든 릴리스 키는 "업로드 키"가 되고,
  Play 가 배포용으로 다시 서명한다. 업로드 키를 잃어버려도 복구 가능해진다
- 출시명: 빌드 번호 그대로 (예: `3`)
- 출시 노트: "초기 측정 버전" 정도면 충분

**테스터 → 이메일 목록 만들기** → 검사자들의 Gmail 주소 추가 (최대 100명)
→ 생성된 **참여 링크**를 폰에서 열고 "테스터 되기" → Play 스토어에서 설치

## 4. 앱 콘텐츠 신고 — 미리 채워둔 답

내부 테스트도 아래 항목을 모두 작성해야 배포된다.
본 앱은 데이터를 수집하지 않으므로 대부분 "아니요"다.

### 개인정보처리방침
URL 이 필수다. 저장소 문서를 그대로 쓸 수 있다.

```
https://github.com/seunghyuk09/PrismTest/blob/main/docs/privacy-policy.md
```
(브랜치가 아직 `main` 이 아니면 실제 기본 브랜치 이름으로 바꿀 것)

### 데이터 보안 (Data safety) — 가장 중요한 항목
| 질문 | 답 |
|---|---|
| 앱이 사용자 데이터를 수집하거나 공유합니까? | **아니요** |
| 모든 사용자 데이터가 전송 중 암호화됩니까? | 해당 없음 (수집·전송 없음) |
| 사용자가 데이터 삭제를 요청할 수 있습니까? | 해당 없음 |

> **주의**: 카메라로 사진을 찍어 기기에 저장하는 것은 Play 기준의 "수집"이 아니다.
> Play 는 **기기 밖으로 전송되는 것**만 수집으로 본다. 본 앱은 INTERNET 권한이
> 없어 전송이 불가능하므로 "수집 없음"이 정확한 답이다.

### 나머지 신고 항목
| 항목 | 답 |
|---|---|
| 광고 포함 | 아니요 |
| 앱 액세스 권한 (로그인 필요) | 모든 기능을 제한 없이 사용 가능 |
| 콘텐츠 등급 설문 | 카테고리: 유틸리티 / 폭력·성적 콘텐츠 등 전부 "아니요" |
| 타겟층 | 18세 이상, 아동 대상 아님 |
| 뉴스 앱 | 아니요 |
| 코로나19 접촉자 추적 | 아니요 |
| 데이터 보안 — 금융 기능 | 아니요 |
| 정부 앱 | 아니요 |
| 민감한 권한 신고 | **불필요** (CAMERA 는 별도 신고 대상이 아니다) |

### 스토어 등록정보
내부 테스트에도 최소한의 등록정보가 필요하다.

- **간단한 설명 (80자 이내)**
  ```
  광학 프리즘 표면 결함 검사용 밝기·대비 측정 도구
  ```
- **자세한 설명**
  ```
  광학 프리즘의 외관 검사를 위한 사내 측정 도구입니다.

  카메라의 노출·ISO·초점·화이트밸런스를 수동으로 고정하고, 화면에 지정한
  두 영역의 밝기 통계와 대비(ΔI/I)를 실시간으로 표시합니다. 조명 조건을
  비교하고 검사 지그의 배경 차광 성능을 수치로 확인하는 데 사용합니다.

  측정 결과는 무손실 PNG 이미지와 CSV 로그로 기기에 저장됩니다.

  이 앱은 네트워크 권한을 요구하지 않으며, 어떤 데이터도 외부로 전송하지
  않습니다. 광고와 분석 도구를 포함하지 않습니다.
  ```
- **앱 아이콘** 512×512 PNG, **그래픽 이미지** 1024×500 PNG, **스크린샷** 2장 이상
  → 앱을 실기에서 돌린 뒤 캡처해서 쓰면 된다

## 5. 업로드 후

내부 테스트 버전은 보통 **수 분~수 시간** 내에 반영된다.
참여 링크로 설치하면 이후 업데이트는 Play 가 자동으로 내려준다.

## 6. 자동 업로드 (나중에)

계정이 준비되면 CI 가 Play 에 자동 업로드하도록 붙일 수 있다.
Play Console → 설정 → API 액세스에서 서비스 계정 JSON 키를 만들어
`PLAY_SERVICE_ACCOUNT_JSON` 시크릿에 넣으면,
푸시할 때마다 내부 테스트 트랙에 새 버전이 올라간다.

지금은 붙이지 않았다. 계정이 없는 상태에서 빌드에 넣으면 매 빌드가 실패하기 때문이다.

## 그동안의 대안 — 사이드로드가 막힐 때

Play 등록에는 며칠이 걸릴 수 있다. 그동안은 APK 로 진행한다.

1. **설정 → 보안 및 개인정보 보호 → 자동 차단 → 끄기** (삼성 폰의 실제 차단 원인)
2. Play Protect 가 "무시하고 설치" 선택지 없이 막으면
   → **Play 스토어 → 프로필 → Play 프로텍트 → 톱니 → "기기 유해 앱 검사" 끄기**
   → 설치 → 다시 켜기
3. 그래도 안 되면 **PC 에서 ADB 설치** — 가장 확실하다
   ```
   adb install -r PrismScope-bN.apk
   ```
   ADB 설치는 Play Protect 의 설치 차단 경로를 거치지 않는다.
   폰에서 개발자 옵션 → USB 디버깅을 켜야 한다.
