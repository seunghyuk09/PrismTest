# v22 실시간 화면과 저장 사진 화질

v22는 **표준 / 정밀** 촬영 모드, **카메라 크게**, 결과 사진의 두 손가락 확대를 추가한다. 정밀 모드는 더 많은 실제 카메라 화소를 요청한다. 저장 원본을 확대 보간하거나 선명화해서 새 화소를 만드는 기능은 아니다.

## 폰에서 사용

1. 검사 화면의 **화질 → 정밀**을 누르고 카메라 연결을 기다린다.
2. 표시되는 **수신 W×H / 저장 W×H**를 확인한다. 수신은 카메라 버퍼 크기, 저장은 화면과 같은 영역으로 잘라 회전을 반영한 원본 사진 크기다.
3. **카메라 크게**를 누르면 조작 패널이 작아지고 실시간 화면이 커진다. 검사 시작 버튼은 화면에 남는다. **기본 화면**으로 설정 패널을 다시 펼친다.
4. 사용할 화면 크기를 정한 뒤 조명·초점·노출을 맞추고 **현재 상태로 고정**한다. 화질이나 화면 크기 변경으로 저장 크기가 달라졌으면 해당 조건의 양품·불량 샘플을 다시 확인한다.
5. 검사 종료 후 결과 사진을 두 손가락으로 확대·이동한다. **확대 초기화** 또는 사진을 두 번 누르면 원래 배율로 돌아간다. 사진 파일의 화소 수는 이 동작으로 변하지 않는다.

| 모드 | 분석 영상 요청 | 용도 |
|---|---|---|
| 표준 | 1280×960 | 기존 작업 흐름과 처리량을 우선하는 기본 모드 |
| 정밀 | 2560×1920 | 지원하는 폰에서 저장 원본의 세부 화소를 늘려 확인 |

요청 크기는 보장 크기가 아니다. 기기에서 제공하는 크기와 Preview + ImageAnalysis 조합에 따라 CameraX가 해상도를 결정한다. 정밀 연결이 실패하면 표준으로 다시 연결하고 화면에 알린다. 프리뷰는 1920×1440을 요청하며, 분석 영상과 같은 센서 영역을 사용한다. 일반적인 지원 목록에서는 프리뷰·표준 분석을 약 2.8MP 이하, 정밀 분석을 약 4.9MP 이하로 제한한다. 지원 크기가 전부 이보다 큰 예외 기기는 가장 작은 실제 지원 크기를 사용한다.

카메라 크게를 사용해 화면비가 달라지면 두 스트림을 같은 새 ViewPort로 다시 연결한다. 재연결 중에는 검사를 시작할 수 없다. 화질 선택과 화면 크기 변경은 검사·결과 저장 중에 막는다.

## 저장과 판정

자동 저장 사진은 점수를 계산한 **동일 프레임의 크롭된 8비트 휘도 영상**이다. 컬러 JPEG나 센서 RAW는 아니다. 정밀 원본도 축소 없이 무손실 PNG로 저장하며, 의심 위치는 그 장면의 좌표로 표시한다. 촬영이 끝난 뒤 다른 각도에서 찍은 고해상도 사진에 이전 좌표를 옮겨 그리지 않는다.

결과 화면에 원본 크기를 표시하고, 사진을 전체 해상도로 읽는다. 화면 배율은 1~8배다. JSON에는 `capture_quality_requested`, `capture_quality_bound`를 추가하며, 장면별 실제 크기는 기존 `frame.display_width`, `frame.display_height`로 남긴다. 기존 v21 기록도 열 수 있다.

기존 디그 검출의 화소 기준과 광학 조건이 그대로이므로 해상도를 높였다는 사실이 검출 정확도 향상을 입증하지는 않는다. 실제 크롭 해상도가 바뀌면 촬영 조건 프로필도 바뀌어 이전 기준으로 바로 합격시키지 않는다. 양품·확인된 불량을 새 조건에서 비교해야 한다. 디그 원은 후보 위치이며 실제 결함 크기를 뜻하지 않는다.

## 폰에서 비교할 조건

- 같은 프리즘·조명·거리에서 표준과 정밀의 **실제 저장 크기**와 원본 사진을 비교한다. 실제 크기가 같으면 요청을 바꿔도 화소 수가 늘지 않은 것이다.
- 폰을 고정하고 프리즘이 선명해지는 거리를 먼저 맞춘다. 디지털 줌을 키우는 것만으로 광학 해상도가 늘지는 않는다.
- 밝은 반사 띠를 피하고 노출을 조절한다. 과노출·흔들림·초점 이탈로 사라진 디그는 저장 화소 수만 늘려 복원할 수 없다.
- 정밀 모드에서 움직임이 끊기거나 반응이 늦으면 표준으로 비교한다. 폰별 처리 속도와 발열은 실제 기기에서 확인해야 한다.

## 검증 실행

```sh
cd android
BUILD_NUMBER=22 ./gradlew testReleaseUnitTest assembleRelease assembleReleaseAndroidTest
# Android 기기 또는 에뮬레이터가 연결된 경우
BUILD_NUMBER=22 ./gradlew connectedReleaseAndroidTest
```

릴리스 빌드와 단위 테스트 **50개**가 통과했다. 지원 해상도 필터와 기존 좌표·기록 처리 등을 포함한다.

Android 계측 테스트에는 2560×1920 영상의 회전 후 크기·화소 보존, MediaStore 저장·결과 표시·실패 정리, CameraX 화질 전환과 화면 크기에 따른 크롭 재연결 확인을 추가했다. 테스트 APK 빌드는 통과했지만 **이번 v22 실행 검증은 미완료**다. Android 11 소프트웨어 에뮬레이터에서 앱 설치 단계에 운영체제가 반복 재시작했고(`Lost network stack`, 패키지 서비스 중단·시간 초과), 계측 테스트 실행에 도달하지 못했다. 이전 v21의 Android 테스트 통과를 v22 통과로 세지 않는다. 실제 폰의 화질·속도도 아직 측정하지 않았다.
