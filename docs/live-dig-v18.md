# v18 Android 실시간 디그 검사

기존 Android 프로젝트 `com.prismtest.scope`를 수정했다. 웹 관리앱이 아니다.
Kotlin·Compose·CameraX 셸을 유지하고 디그의 국소 점 후보 검출은 독립적인 C++17 코어로 추가했다.
기존 네 유형의 특징 계산은 Kotlin에 남아 있으며 전체 알고리즘의 C++ 통합은 완료한 상태가 아니다.

## 설치와 첫 사용

빌드된 `PrismScope-v18-dig.apk`는 버전 코드 18이며 GitHub v17 APK와 패키지와 서명 인증서가 같다.
v17을 지우지 않고 업데이트할 수 있는 조건을 파일에서 확인했다. 실제 휴대폰 설치는 별도로 검증해야 한다.

1. 카메라 권한을 허용하고, 폰·조명을 고정한다. 작은 차광 후드 또는 주변 반사를 줄이는 검은 배경으로 시작한다.
2. 기본 선택은 **디그**다. 검사면의 어두운 부분을 눌러 노란 영역을 맞추고 ±로 크기를 조절한다. 밝은 띠·모서리·손가락을 피한다. 검사 범위는 선택한 영역뿐이며 세 면 전체를 확인했다는 의미가 아니다.
3. 카메라가 잘 보이는 상태에서 **현재 상태로 고정**을 누른다. 실제 적용된 노출·초점·화이트밸런스를 확인할 때까지 검사 버튼은 대기한다.
4. 실시간 노란 원은 **점 형태의 후보 위치**다. 한 프레임에 없다는 이유로 양품을 확정하지 않는다. 밝은 점만으로 디그·먼지·흰색 이물·기포가 완전히 구별되는 것은 아니다. 화면 혼잡을 줄이기 위해 강한 후보 최대 8곳만 표시한다.
5. **샘플 등록**에서 서로 다른 양품 5개 이상, 해당 유형의 서로 다른 불량품 3개 이상을 같은 조건으로 등록한다. 샘플 최소 개수는 운영 시작 조건이며 통계적 검출률을 보증하는 수가 아니다. 같은 제품의 여러 프레임·반복 측정을 서로 다른 제품으로 세지 않는다.
6. 분포가 겹치거나 불량 분포가 역전되면 양품을 확정하지 않고 재검으로 남긴다. 등록하지 않은 유형은 기준 없음이다. 검사 유형 선택에서 활성화한 유형만 최종 판단한다. 미선택 유형은 검사하지 않은 것이다.
7. 검사 시간 동안 제품을 천천히 기울여 여러 관찰 조건을 확보한다. `관찰 변화` 표시는 밝기 변화의 참고 지표이며 실제 회전 각도·세 면 커버리지 측정값이 아니다. 유효 영상이 부족하거나 촬영 조건이 바뀌면 측정 불가·재검으로 표시한다.

자동 추적은 밝은 띠나 손가락을 따라갈 수 있어 새 기본값은 수동이다. 사용자가 저장한 기존 추적 설정은 유지한다.
다른 유형도 검사하려면 해당 유형을 선택하고 그 유형의 기준을 등록한다. 양품 등록은 선택한 유형에만 반영된다.

## 기준과 촬영 조건

학습 경계는 기기·카메라·분석 해상도·ISO·셔터·초점·줌·화이트밸런스 조건 키와 연결한다.
조건이 달라진 기준으로는 양품을 표시하지 않는다. 조건이 없는 예전 샘플은 보존하되 현재 기준으로 사용하지 않는다.
기준을 바꾸려면 설정에서 해당 유형을 초기화하고 재등록한다. 초기화에는 확인 창이 있으며 이미지·CSV 파일은 삭제하지 않는다.

이 키는 렌즈 교정·px/mm·거리·조명 위치·기기 간 등가성 시험을 대신하지 않는다. 폰·제품 거리와 조명도 실제로 고정해야 한다.
디그 모드는 국소 대비를 사용하므로 기존 네 유형의 암시야 중앙값 기준을 그대로 적용하지 않는다. 넓은 포화·반사 구역은 여전히 유효 검사에서 제외한다.

## 검출 코어

- 밝기 적분 영상으로 각 화소 주변의 고리 모양 배경 평균을 계산한다.
- 국소 배경과의 차이 및 잡음 수준으로 밝은 점 후보를 추출한다.
- 넓은 강한 반사광과 그 경계를 가리고, 큰 덩어리·길쭉한 선·영역 경계 후보를 제외한다.
- 점의 위치·산란 대비·화소 면적을 반환한다. 이 값은 물리적인 디그 직경이 아니다.
- CameraX 프리뷰와 분석에 같은 ViewPort를 사용하며, Y 평면의 cropRect·rowStride·pixelStride·buffer offset·회전을 반영해 표시한다.

디그 유형 키는 새 `dig_v1`이다. 기존 흰색 이물 기준을 디그 기준으로 재사용하지 않는다.
한 불량 제품에 디그 두 곳이 있어도 불량 제품 수는 1개다. 디그의 mm 크기 및 Scratch-Dig 60/40 합부 판정은 이 코어가 측정하지 않는다.

## 사용자 영상으로 확인한 범위

`Video Project 2.mp4`의 2.0초 프레임에서 사용자가 지목한 두 디그 위치를 확인 자료로 사용했다.
원본 기준 (470, 990)에서 160×160 영역을 자른 그레이스케일 픽스처와 출처 JSON을 테스트 리소스에 보관한다.
두 지목 위치는 코어의 상위 1·2순위 점 후보와 일치했다. 다른 작은 점들은 미분류 상태이므로 오검으로 단정하지 않는다.

이 검증은 **한 개 제품·한 장면의 위치 회귀 검사**다. 양품 모집단의 오검률, 불량 모집단의 미검률, 손 움직임 전 구간의 추적 성능을 검증한 것은 아니다.
첫 번째 영상은 양불량 라벨과 두 번째 영상과의 개체 동일성이 확인되지 않아 양품 기준으로 사용하지 않았다.

도움말의 실제 디그 예시는 같은 Kotlin → JNI → C++ 경로로 계산한다. 예시 영역 좌표는 해당 참고 사진에서만 사용하며 실시간 카메라의 검출 위치로 고정하지 않는다.

## 저장과 호환성

PNG는 분석 프레임의 crop과 회전을 반영해 저장한다. CSV의 점 좌표는 그 이미지 방향의 정규화 좌표다.
새 열이 추가되어 로그 이름을 `prismscope_log_v2.csv`로 분리했다. 이전 CSV에 다른 열 구조의 행을 덧붙이지 않는다.
현재 프레임의 점 위치와 스윕의 유형별 최고점은 서로 다른 값이므로 별도 열에 보존한다.

## 빌드와 검증

필요 도구: JDK 17 이상, Android SDK 35, Build Tools 35.0.0, NDK 27.0.12077973, CMake 3.22.1.
Gradle 8.9 wrapper와 배포 ZIP은 공식 체크섬으로 검증한다. 저장소의 서로 맞지 않았던 wrapper 스크립트·JAR를 같은 공식 8.9 버전으로 맞췄다.
출력 ABI는 arm64-v8a와 x86_64, 최소 Android 10(API 29)이다.

```bash
cd android
BUILD_NUMBER=18 ./gradlew --no-daemon --max-workers=2 :app:assembleRelease :app:testReleaseUnitTest
cd ..
python3 analysis/validate_dig.py --sanitize --report /tmp/prism-native-validation.json
```

이 작업에서 릴리스 APK 빌드, Kotlin 회귀 검사 12개, C++ 합성·사용자 장면 회귀 검사(ASan/UBSan 포함)가 통과했다.
컴파일된 Kotlin과 JNI/C++ 사이의 실제 호출, 점 좌표, 90도 회전, 잘못된 버퍼 거부도 호스트 JVM에서 확인했다.
APK의 서명, 버전 증가, release debuggable 해제, 네트워크 권한 부재, 두 ABI 라이브러리 포함을 파일에서 확인한다.
**갤럭시 Z 폴드 7의 실제 카메라 및 현장 조명 검증은 아직 수행하지 않았다.** 실물 양품·불량을 새로 등록하고 현장에서 확인해야 한다.
